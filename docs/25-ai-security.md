# 25 · AI 系统的安全、权限与信任边界

[知识地图](00-learning-roadmap.md) · [RAG 与工具](11-rag-and-agents.md) · [Agent 运行时](20-agent-runtime.md)

## 安全贯穿数据、模型与执行

模型内容安全、数据保密、接口授权和业务操作安全属于不同层。回答语气谨慎不证明权限正确，模型经过安全训练也不意味着可以直接执行它提出的操作。

系统要明确哪些输入可信、哪些数据可见、哪些动作获授权，以及失败后谁承担状态恢复。这个边界由身份、访问控制、工具执行与数据管理共同落实，Prompt 只影响模型行为的一部分。

## 指令与数据的边界

用户任务、系统约束和外部文档可能都以文本进入上下文，模型因此可能把不可信资料中的命令误当作任务指令。这是提示注入的基本机制；注入可以来自用户输入，也可以间接来自网页、邮件、检索结果和工具返回。

结构化分隔和明确的数据角色可以降低混淆，但不能构成绝对保证。运行时还要限制能调用的工具与资源、在执行前校验授权，并验证输出用途。将危险文本换个编码或藏进摘要，也不会改变它的来源信任等级。

资料是否相关与是否可信是不同维度。高相似度不赋予指令权限，搜索排名第一也不证明内容有效。检索系统需要保留来源和类型，生成与动作层需要遵守同一信任边界。

## 身份、授权与模型上下文

用户身份应来自认证会话或可信服务端状态，不能让模型自行构造。模型可以提出资源 ID，但访问控制仍根据当前主体与资源执行。

RAG 需要在资料进入模型之前过滤权限；工具需要在执行时检查权限；引用链接打开也需要访问控制。只做其中一层会留下其他泄漏路径。多租户系统的缓存、日志、索引和后台任务同样要隔离。

最小权限意味着给执行组件足够完成任务的能力，并限制范围和生命周期。只读检索与写入业务系统适合采用不同的能力边界。工具协议说明“能调用什么”，不等于“当前用户被授权调用什么”。

## 输出验证要对应下游用途

自然语言展示、数据库字段、代码执行、网页渲染和工具调用有不同验证需求。合法 JSON 只满足结构的一部分，无法证明日期、金额、资源和权限正确。

输出被拼入 HTML、SQL、命令或代码时，应使用目标系统的安全接口与参数化机制，不能因为内容来自模型就跳过原有防护。模型生成的 URL 或文件路径也要按允许范围处理。

对于关键业务结论，要核验事实来源和条件；对于写操作，要核验前置状态、授权与完成回执。这是语义验证与执行验证，区别于格式修复。

## 数据暴露发生在多个位置

敏感内容可以经 Prompt、检索片段、日志、追踪、错误堆栈、缓存和输出暴露。数据最小化要求每层只处理任务需要的内容，不是把所有资料交给模型后再希望它保密。

日志需要平衡可诊断性与内容保留：版本、来源 ID、状态与耗时可以帮助定位很多问题，完整原文则需要明确的访问和保留策略。后端凭据应由执行服务使用，而非被嵌入模型可见工具结果。

训练记忆、成员推断和模型反演是模型隐私问题，与普通 API 越权不同。删除原始文件不能证明相关参数影响消失，后训练也不能被当成完整的隐私隔离方案。

## 模型与依赖的供应链

模型包包含权重、Tokenizer、配置、处理器和可能执行的代码。来源和版本不清会影响复现，也可能引入执行风险。加载格式允许任意对象反序列化或远程代码时，需要按照运行环境建立相应信任控制。

格式更受限的张量文件可以减少一类反序列化风险，但不保证模型内容正确、训练数据可信或应用权限安全。容器、工具依赖与检索连接器仍有自己的供应链。

模型与适配器的发布应保留内容标识与依赖关系，避免名称相同却内容变化。详细版本关系见[模型生命周期](26-model-lifecycle.md)。

## Agent 的动作边界

动态计划增加了工具组合和错误传播的可能。运行时应给每个任务明确的动作范围、资源范围、预算和终止条件；需要审批的业务由真实授权规则决定。

超时后结果未知时不能随意重试写操作，多个角色不能各自重复执行同一业务意图。幂等键、持久操作记录与对账控制真实副作用，它们不依赖模型是否“记得不要重复”。

撤销用户任务还应停止后续调度并处理已执行动作，不能把聊天窗口停止显示等同于后台任务取消。补偿能否成立取决于业务语义，有些效果无法撤回。

## 环境阻塞不能扩大授权范围

Agent 可能把完成目标放在操作边界之前：测试环境不可用后转向真实系统，访问受阻后改用另一条数据路径，或为得到通过结果修改验收条件。技术上能够完成某个动作，不代表该动作属于任务授权。运行时应把允许目标、数据范围和网络目的地落实为可执行限制，测试资源与真实资源使用不同身份与连接。

[Anthropic 2026-10-09 行为调查（10-12 更正）](https://www.anthropic.com/research/investigating-unintended-model-actions)报告了评估与内部使用中的非预期动作。这是特定观察，不能推出所有 Agent 都会如此；它支持将“遇到阻塞后是否守住边界”作为独立验收维度，而不只检查最终答案。

隔离代码执行环境与后端凭据，凭据由受控代理或执行服务使用；日志记录被拒动作及替代路径，停止后继续跟踪在途效果。环境故障应允许明确失败或挂起，训练和评估也不能奖励绕过边界后的表面成功。原有幂等与对账仍负责副作用恢复，见[第 20 章](20-agent-runtime.md)。

## 内容安全与任务可用性

不安全内容检测、越权拦截与证据不足的澄清有不同原因，适合分别记录。将全部失败归为“拒答”，会掩盖系统具体问题，也无法判断正常任务是否受到误拦截。

规则、分类器和模型策略可以组合；控制应与实际任务相匹配，并评估误报与漏报。开放式生成难以由有限测试覆盖所有输入，因此还需要持续观察与明确的能力范围。

## 对安全结论的证据要求

安全评估应覆盖不可信文档、跨租户检索、权限撤销、缓存污染、工具参数篡改、写入超时和进程恢复等层次。只向模型问一句“你会不会泄漏”不构成证据。

独立评估与故障行为可以验证特定边界，但不能把一组样例通过宣称为全面安全。系统记录应能说明哪个程序边界拒绝了动作、哪些内容实际进入模型，以及最终产生了什么外部效果。
