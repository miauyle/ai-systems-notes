# 09 · 推理、KV Cache 与资源管理

[返回目录](../README.md) · [下一章](10-serving-and-distributed.md)

## 缓存消除的是哪种重复工作

普通因果 Transformer 的历史位置不能读取未来，因此在权重、输入和位置规则不变时，给前缀追加 Token 不改变旧位置的各层表示。不使用缓存时，每轮可把整个前缀重新跑一遍，重新生成全部历史 K/V；结果可正确，但大量投影、FFN 和注意力工作重复。

KV Cache 保存各层已经计算好的历史 K/V，让下一轮只计算新位置的表示。它不是模型参数、聊天记录或数据库，更不保存未来答案。下面只讨论标准全因果注意力；滑窗、压缩状态和其他架构需按实际状态规则分析。

## Prefill 怎样逐层建立缓存

设提示词含 `T` 个 Token。先完成 Tokenization 和 Embedding，再依次处理模型各层。在第 `l` 层：

1. 这一层读取上一层输出，对本层输入做 Norm 与 Q/K/V 投影。这里有 `T` 个新查询和 `T` 个新 K/V；不是把第一层 K/V 复制到后续层。
2. 按本层位置机制处理 Q/K。常见 RoPE 实现缓存已经施加位置旋转的 K，V 通常不旋转；实际缓存格式以算子约定为准。
3. 按因果关系计算提示词内部注意力，将这些位置的 K/V 写到属于该请求、该层的缓存位置。写缓存与计算注意力可由实现融合或重排，必须保证后续读取正确。
4. 完成输出投影、残差、FFN，得到本层全部位置的输出，供下一层生成它自己的 K/V。

全部层完成后，末端隐藏状态经过最终 Norm 与 LM Head，提供第一个输出 Token 的 logits。Prefill 并行的是同层已知位置，并非所有层无依赖地同时执行。

## Decode 怎样读取历史并追加状态

采样得到的第一个输出 ID 作为下一轮输入。在每层，新位置产生自己的 Q、K、V；K/V 追加到该层缓存，新 Q 读取本层历史加自身的 K/V，汇总后完成该层剩余计算。只需一个新查询，但它面对的键集合仍是整个有效前缀。

| 时刻 | 输入本轮真正处理的位置 | 每层缓存完成后的有效长度 | 末端 logits 用于选择 |
| --- | --- | --- | --- |
| 提示词 Prefill 完成 | 提示词全部 `T` 个位置 | `T` | 第一个输出 Token |
| 第一次增量前向完成 | 刚选出的第一个输出 Token | `T+1` | 第二个输出 Token |
| 后续增量前向完成 | 上一轮选出的 Token | 再增加一个 | 下一个输出 Token |

**采样本身不写 K/V。**最后已经发给用户的 Token，若随后停止，就可能没再进入网络。引擎必须区分“已生成 ID 数”“已计算的缓存位置数”和“分配的容量”，它们不是同一个计数。

批量 Decode 时，每个请求有自己的长度、块表和位置。将多个请求放进一个 GPU 批次不允许它们互读历史。一次续写多个已知 Token、分块 Prefill 或推测验证时，新增查询之间也要按全局位置执行因果约束，不能一概当成相互独立的单 Token。

## 为什么缓存 K/V，通常不缓存旧 Q

未来位置发起新的查询，需要历史的匹配键和内容值。旧 Q 已经用于生成旧位置输出，标准增量前向不会再次要求它发起查询；保留旧 Q 通常没有复用价值。

这是一条因果依赖结论，不是“K/V 算得更贵”。若修改旧前缀，从受修改位置开始的后继表示可能变化，旧缓存就不能继续用。改变权重、LoRA、位置规则或影响前向的输入也要重新判断复用。双向模型追加输入会影响旧位置，不能直接套这套规则。

## KV 的逻辑形状与容量

设 `h_q` 是查询头数，`h_kv` 是 K/V 头数，单头宽度为 `d_h`。在 K、V 宽度相同的常见设计里，每层一个请求的两份缓存逻辑形状均为 `[h_kv,T,d_h]`；实际内存可能按块、头、位置转置存储。

标准未分片、无共享、等宽各层的原始有效 KV 字节数为：`2 × L × h_kv × d_h × 每元素字节数 × 所有缓存序列的有效长度之和`。如果 K/V 宽度、层结构或缓存格式不同，须逐层分别计算。量化格式还可能带缩放和其他元数据。共享前缀按实际物理块去重，多卡预算还要计复制而非一律按卡数均分。

```math
\text{推理显存}\approx\text{权重}+\text{KV Cache}+\text{激活/工作区}+\text{运行时开销}
```

容量预算要计分配块，而不只计有效 Token；还需预留 Prefill 峰值、通信、图执行缓冲和输出增长。GiB 是 `2^30` 字节，GB 是 `10^9` 字节，比较工具数据时统一单位。权重能加载只是起点，不保证请求运行时不 OOM。

## 混合状态要按物理对象计算容量

前面的等宽 KV 公式针对每层独立保存普通 K/V 的模型。遇到递归、滑窗和跨层复用，应先按[架构](06-modern-architectures.md)列出实际对象，再统计存储：

| 状态 | 随历史增长的方式 | 容量容易漏算什么 |
| --- | --- | --- |
| 全局 Attention KV | 通常随保留位置增长；压缩模型按实际表示计算 | 压缩索引、量化尺度、分片或复制 |
| Sliding-Window Attention（SWA，滑窗注意力）KV | 活动窗口受限，旧位置可按模型规则退出 | 多层状态不同；恢复不能只看单层窗口 |
| 递归状态 | 固定配置下通常维度固定，内容逐步更新 | 分支快照、临时验证状态及其他局部历史 |
| 跨层共享对象 | 物理数据可由多个层引用 | 引用关系、层私有状态与工作缓冲仍存在 |

逻辑层数不等于物理缓存副本数；共享数据不能重复计费，层私有状态也不能被一并省掉。模型权重量化与缓存量化分别核算。容量报告还要区分运行中 HBM 驻留、主机暂存和供后续请求复用的持久缓存，不能将某一类缓存的压缩比例推广到全部推理内存。

对活动请求，只保存当前递归状态可以继续推进；若要从较早前缀恢复，需要对应位置的快照或按原输入重建。状态“小”与任意位置都能廉价恢复不是一回事。分叉、推测拒绝和重建边界见[第 18 章](18-inference-engineering.md)。

## GQA、PagedAttention、Prefix Cache 不解决同一件事

| 技术 | 改变什么 | 保留什么工作 | 工程边界 |
| --- | --- | --- | --- |
| MQA / GQA | 多个 Q 头共享更少 K/V 头，改变模型的头对应关系 | Q 头仍各自做信息选择，仍访问有效历史 | 需要对应权重/训练；实际复制 KV 会抵消收益 |
| PagedAttention | 逻辑连续序列映射到不必物理连续的 KV 块 | 不减少模型所需有效历史或注意力关系 | 块表访问、尾块浪费、生命周期与并发安全 |
| Prefix Cache | 匹配同一计算前缀时复用其已计算各层 K/V | 未命中后缀还要处理，后续 Decode 仍读取前缀 | 内容与执行配置必须匹配，共享块不能随意改写 |

GQA 压缩“每个位置保存多少状态”，分页改善“这些状态如何放和回收”，前缀复用减少“相同状态算几次”。三者可以组合；不是三种名称不同的聊天缓存。详细分配、共享与淘汰见[第 18 章](18-inference-engineering.md)。

## 缓存省计算，仍会带来读流量

全注意力 Prefill 的查询—键关系数随输入长度平方增长；缓存后的单步 Decode 只处理新增查询，但要读取增长的历史 K/V。Decode 总耗时还包含权重访问、投影、FFN、通信与调度，不能只用历史长度预测。

批处理可以让多个新 Token 共同复用权重读取，代价是更多活跃 KV 与排队；长输出还使请求持续占用状态。缓存卸载可以释放 HBM，却把下一次读取变成搬运与等待。性能和容量是相关但不同的约束，硬件数据路径见[第 27 章](27-compute-infrastructure.md)。

## logits 到 Token：采样也有状态

解码可先应用格式约束、惩罚等处理，再按约定执行 Temperature、Top-k/Top-p 与选择。温度缩放改变分布，截断改变候选集合并需重新归一化；Greedy 选当前最高分，不保证整个序列最优。不同处理顺序可能产生不同分布，应与生成配置一同记录。

低温度不是事实校验。结构化约束只限制可输出形式，不能证明字段值正确。采样随机状态、停止规则和累计文本属于生成状态，不属于 KV。EOS、长度上限或停止字符串触发结束后，服务还要处理已缓冲输出和缓存回收，见[请求生命周期](10-serving-and-distributed.md)。
